## 后端业务主链路

1. **用户与导航**：首页、搜索、分类、附近店、批发选品、个人中心、消息通过统一用户身份和底部导航串联。
2. **商品交易**：商品/店铺浏览 → SKU 与优惠计算 → 确认订单 → 微信担保支付 → 商家发货 → 物流跟踪 → 收货/评价/发票。
3. **拼团与秒杀**：活动配置库存、时间窗、限购和成团状态，订单支付后锁定或扣减库存。
4. **售后**：申请 → 商家审核 → 寄回/签收 → 退款或换货 → 平台介入，需记录状态流转、凭证和时限。
5. **分销**：邀请关系、一级归因、佣金冻结/结算/提现，关联分销商品和邀请记录。
6. **批发**：选品单暂存 → 确认收货地址 → 批发订单支付 → 发货/收货 → 私域评价与售后。
7. **商家工作台**：入驻资质审核 → 商品/SKU → 营销活动 → 订单履约 → 售后处理 → 数据与客服。

## 通用技术要求

- 所有订单、支付、库存、退款操作使用状态机和幂等号。
- 金额使用 `BigDecimal`，库存扣减采用事务与乐观锁/分布式锁。
- 页面按钮对应 REST API，关键动作记录操作日志与消息通知。
- 分页、筛选、排序、时间范围和权限校验由后端统一处理。

## 微服务总体架构规划

### 1. 设计目标

- 采用 Spring Boot 3.x + Spring Cloud 2023.x，JDK 21，完全微服务化，不建设单体应用。
- 目标容量按 10 万在线用户设计，核心接口支持水平扩容，秒杀、支付、库存链路具备独立限流和降级能力。
- 读多写少场景优先缓存和搜索，交易场景优先数据一致性、幂等和可追溯。

### 2. 服务拆分

| 服务 | 主要职责 | 数据边界 |
|---|---|---|
| gateway-service | 统一入口、鉴权、限流、灰度、路由 | 无业务表 |
| auth-service | 微信登录、JWT、刷新令牌、权限 | 用户认证库 |
| user-service | 用户、好友、收货地址、设置 | 用户库 |
| catalog-service | 分类、商品、SKU、品牌、评价 | 商品库 |
| shop-service | 店铺、关注、附近店、营业状态 | 店铺库 |
| search-service | 商品/店铺/批发搜索、排序、筛选 | Elasticsearch |
| marketing-service | 红包、优惠券、满减、礼金、秒杀、拼团 | 营销库 |
| cart-service | 购物车、选品单、批发当前订单 | Redis + 购物车库 |
| order-service | 普通订单、批发订单、订单状态机 | 订单库 |
| payment-service | 微信支付、退款、分账、支付回调 | 支付库 |
| inventory-service | 库存、锁定、释放、扣减 | 库存库 |
| fulfillment-service | 发货、物流、配送、运单 | 履约库 |
| aftersale-service | 售后申请、审核、换货、退款协同 | 售后库 |
| merchant-service | 入驻、资质、商品管理、商家工作台 | 商家库 |
| distribution-service | 一级分销、邀请关系、佣金、提现 | 分销库 |
| message-service | 订单通知、系统公告、站内信、客服会话 | 消息库 |
| file-service | 图片、视频、资质、评价凭证上传 | OSS 元数据 |
| admin-service | 平台规则、审核、运营配置、风控 | 管理库 |

每个服务独立数据库和独立 Flyway/Liquibase 迁移，服务之间通过 REST/OpenFeign 调用查询，通过 Kafka/RocketMQ 发送领域事件，禁止跨服务直接访问数据库。

### 3. Spring Boot 全家桶

- Spring Boot、Spring MVC、Validation、Actuator。
- Spring Cloud Gateway、LoadBalancer、OpenFeign、Config、CircuitBreaker。
- Spring Authorization Server 或 JWT/OAuth2 Resource Server。
- Spring Cloud Alibaba Nacos、Sentinel、Seata。事务边界优先本地事务加可靠事件，Seata 仅用于少量强一致场景。
- Spring Data Redis、MyBatis-Plus、分库分表中间件 ShardingSphere。
- Spring Kafka 或 RocketMQ Spring，统一事件模型、重试队列和死信队列。
- Micrometer、Prometheus、Grafana、OpenTelemetry、SkyWalking。

### 4. 基础设施

- Kubernetes 部署，Gateway、订单、支付、库存、搜索、消息等服务分别配置 HPA。
- Nginx/云负载均衡 → Gateway 集群 → 微服务集群。生产环境至少三可用区。
- MySQL 8 主从或高可用集群，按用户、订单、商品等领域拆库，订单和支付按时间或用户分片。
- Redis Cluster 做缓存、分布式锁、令牌桶、购物车和热点数据，禁止把 Redis 当唯一订单数据源。
- Elasticsearch 承载搜索和附近店查询，MySQL 通过事件异步同步索引。
- Kafka/RocketMQ 集群承载订单、支付、库存、售后、通知事件。对象文件使用 OSS/COS，CDN 分发图片和视频。

### 5. 10 万在线容量策略

- 在线用户不等于瞬时请求，容量测试按 10 万 WebSocket/长连接、峰值 2 万至 5 万 QPS 进行压测并以实测结果校准。
- Gateway 无状态部署，JWT 本地校验，避免每次请求访问认证中心。
- 热门商品、活动详情、店铺首页、分类数据使用 Redis + 本地 Caffeine 两级缓存，设置随机过期时间防止雪崩。
- 秒杀采用预热库存、Redis 原子扣减、用户限购键、消息异步下单，订单服务二次校验库存和价格。
- 使用 Sentinel 对登录、搜索、下单、支付回调、客服接口分别限流，配置熔断、舱壁和降级响应。
- 数据库连接池、线程池、HTTP 客户端连接数按压测结果配置，禁止无界线程池和同步调用链过长。
- 读写分离、分页游标化、批量查询和异步化处理，避免深分页及 N+1 查询。

### 6. 交易一致性与状态机

- 下单使用幂等键 `requestId`，订单、支付、退款、售后、发货接口重复请求返回同一业务结果。
- 订单创建流程为价格快照 → 优惠试算 → 库存预占 → 创建订单 → 发布待支付事件。任一步失败执行补偿释放库存。
- 支付回调先验签，再以支付流水号幂等更新支付单，发布支付成功事件，禁止依赖前端支付结果。
- 库存采用预占、支付扣减、超时释放三段式状态，定时任务扫描加消息补偿双保险。
- 使用 Outbox/本地消息表保证数据库提交与事件发布最终一致，消费者必须幂等。
- 退款、佣金、分账均保留资金流水、业务单号、渠道单号和审计日志。

### 7. 安全与运维

- 网关统一 TLS、签名校验、参数校验、黑名单、接口级 RBAC，敏感字段脱敏和加密存储。
- 文件上传进行类型、大小、内容安全校验，下载使用短时签名 URL。
- 日志采用 TraceId 贯穿网关、服务、消息和数据库，集中到 ELK/OpenSearch。
- Prometheus 监控 QPS、P99、错误率、线程池、连接池、缓存命中率、消费积压、库存异常和支付回调延迟。
- 灰度发布、滚动发布、自动回滚，数据库变更先扩展后收缩，配置和密钥进入配置中心与密钥管理系统。

### 8. 推荐项目结构

每个服务独立 Maven 工程，内部采用 `api`、`application`、`domain`、`infrastructure`、`interfaces` 分层。公共 starter 仅放日志、异常、响应体、鉴权、幂等和链路追踪，禁止把业务代码放进公共包。

### 9. 分阶段落地

1. 第一阶段建设网关、认证、用户、商品、店铺、搜索、购物车、订单、支付、库存基础链路。
2. 第二阶段接入优惠营销、秒杀拼团、物流、售后、消息客服和商家工作台。
3. 第三阶段建设分销钱包、批发域、平台运营、风控、数据报表和全链路压测。
4. 上线前完成容量基线、故障演练、消息积压恢复、支付重复回调、库存超卖和 Redis 故障演练。
